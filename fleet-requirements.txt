# fleet-requirements.txt -- the always-on fleet's Python dependencies.
# Source of truth for the dedicated fleet virtual environment.
#
# WHY THIS EXISTS
# The fleet used to run on a shared, per-user Python install whose packages were
# split between the interpreter's Lib\site-packages (visible to the Windows
# service account) and the roaming user-site %APPDATA%\Python (NOT visible to it).
# "It imports in my shell" said nothing about whether the service could import it.
# A dedicated venv disables user-site by default, so that whole class of bug is
# designed out: one site-packages, account-independent, pinned, reproducible.
#
# HOW TO (RE)BUILD THE FLEET VENV  (non-elevated; run from the Supervisor dir)
#   py -3.13 -m venv fleet-venv
#   fleet-venv\Scripts\python -m pip install --upgrade pip
#   fleet-venv\Scripts\python -m pip install -r fleet-requirements.txt
#   fleet-venv\Scripts\python -m pip install -e E:\DevPython\SharedPyLib   # jwc_pylib (editable)
# Then point the nssm service at fleet-venv\Scripts\python.exe (one elevated step).
# fleet-requirements.lock.txt holds the exact resolved versions (pip freeze) for
# byte-for-byte reproduction; this file is the human-readable intent.
#
# SCOPE: only what the 22 supervised fleet parts import at runtime. Interactive
# dev/report tools (pytest, playwright, pypdf, reportlab, matplotlib, ...) are
# deliberately NOT here -- run those under the dev interpreter, not the fleet.
# jwc_pylib is installed editable (see above) and brings keyring + psycopg2-binary.
